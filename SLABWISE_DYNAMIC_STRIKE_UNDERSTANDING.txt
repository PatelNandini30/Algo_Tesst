================================================================================
 SECTION 1 — THE IDEA IN ONE PARAGRAPH
================================================================================

Today, a leg's strike is chosen ONCE by a fixed rule (e.g. "always sell the
OTM 2% put"). "Slabwise Dynamic Strike" replaces that fixed rule with a
USER-DEFINED GRID. At every entry the engine looks at WHERE the market is —
how far it has moved (the "ROC slab", the ROW) and how many staircase-style
down-legs it has taken (the "active pivot", the COLUMN) — and reads the strike
offset out of the grid cell where that row meets that column. As the market
grinds down, the cell selected walks the strike progressively from OTM toward
ITM (or whatever gradient the user types into the grid). The market's structure
is tracked by a chain of PIVOTS and PEAKS built off the daily index close.


================================================================================
 SECTION 2 — VOCABULARY (PRECISE DEFINITIONS)
================================================================================

PIVOT 1   = The phase start. Its close is the anchor of the whole chain.
            (Your example: 18700.)

PEAK 1    = The HIGHEST close seen since Pivot 1. It trails UP only.

*** USER CONSTRAINT (added): PEAK 2 MUST ALWAYS BE GREATER THAN PEAK 1. ***
    Generalised: peaks are STRICTLY INCREASING across cycles
    (Peak1 < Peak2 < Peak3 < ...). The peak is therefore a GLOBAL RUNNING
    MAXIMUM that only ratchets UP and NEVER resets down to a new pivot.
    A new pivot cycle (advancing the column) is recognised ONLY AFTER the
    market prints a NEW HIGH above the previous cycle's peak and THEN falls N%
    from that new high.
    BIG CONSEQUENCE: in a pure downtrend made of LOWER highs, NO Pivot 3/4...
    ever forms. Pivot 2 simply keeps TRAILING DOWN to capture the drawdown low.
    The staircase only steps to the next column on a higher-high-then-N%-fall.

N%        = The single user-defined fall threshold (your example: -5%). It is
            the SAME for every cycle of the staircase.

PIVOT 2   = The FIRST close that is N% or more below Peak 1. Once set, it
            TRAILS DOWN only: every new LOWER close becomes the new Pivot 2.
            It never trails back up.
            (Your example: Peak1=1000, close 949 = -5.1% -> Pivot2 = 949;
             later close 935 -> Pivot2 = 935; a close of 960 does NOT move it.)

PEAK 2    = A NEW running-max high that is STRICTLY GREATER THAN PEAK 1, made at
            some point after Pivot 2. Until such a higher high prints, there is
            no Peak 2 and hence no Pivot 3.
PIVOT 3   = The first close N% below Peak 2. Trails down. ...and so on, with
            Peak 3 > Peak 2 required for Pivot 4, etc.

So the staircase is:
   Pivot1 -> (Peak1) -> Pivot2 (trails down) -> [wait for NEW HIGH > Peak1 = Peak2]
          -> Pivot3 -> [wait for NEW HIGH > Peak2 = Peak3] -> Pivot4 -> ...

ROC       = "Rate of Change" — a percentage move used to pick the SLAB (the row).
            *** WHICH two points define this % is OPEN QUESTION A — see Sec 7. ***
            Working assumption in this doc: ROC = % change of the current close
            vs the PIVOT 1 anchor (cumulative). Flagged everywhere it matters.

SLAB      = A user-defined ROC band (row). Example bands: 0-5, 5-10, 10-15,
            15-20, 20+. Boundaries are user-editable.

ACTIVE PIVOT = Which pivot is currently the latest one established as of the
            entry date. Before any N% fall happens we are on Pivot 1; after the
            first N% fall we are on Pivot 2; etc. This selects the COLUMN.

GRID CELL = grid[ ROC slab (row) ][ active pivot (column) ] = the strike offset
            (ITM/ATM/OTM, value, in % OR points) to use for THIS entry.


================================================================================
 SECTION 3 — THE PIVOT / PEAK ENGINE, STEP BY STEP
================================================================================

Walk the daily index closes left to right. Maintain four things:
   * active_pivot_index  (starts at 1)
   * current_pivot_close (starts = Pivot 1 close; trails DOWN within a cycle)
   * running_peak        (GLOBAL running max; starts = Pivot 1 close; UP only,
                          NEVER resets down -- enforces Peak2 > Peak1 > ...)
   * peak_at_last_pivot  (the peak value locked when the last pivot fired;
                          starts = Pivot 1 close)

For each new daily close C:
   1. If C > running_peak:  running_peak = C        (peak ratchets UP only)
   2. trigger = running_peak * (1 + N/100)          (N=-5 -> trigger = peak*0.95)
   3. If C <= trigger:
        a. If running_peak > peak_at_last_pivot:     <-- a NEW, HIGHER peak exists
              => NEW CYCLE: active_pivot_index += 1
                            peak_at_last_pivot = running_peak   (this is Peak_k,
                              guaranteed strictly > the previous peak)
                            current_pivot_close = C
        b. Else (no new higher high since last pivot):
              => SAME CYCLE: current_pivot_close = min(current_pivot_close, C)
                 (Pivot just TRAILS DOWN; column does NOT advance)

KEY POINT: running_peak NEVER resets to the new pivot. That is what guarantees
Peak2 > Peak1, and it is why a downtrend of LOWER highs only trails Pivot 2 and
never reaches Pivot 3.

NUMBER-LINE PICTURE (N% = -5%), reflecting the Peak2>Peak1 rule:

  18700(P1)            19500(Peak1)
     |---------- rises ----------|
                                  \  fall 5% from 19500 -> 18525 trigger
                                   18500 <= 18525  => PIVOT 2 @ 18500
                                     \
                                      18000 (new low) => Pivot2 TRAILS to 18000
                                        /
                                   recover to 19200 (LOWER high, < 19500)
                                        \  fall again to 18100
                                         18100 -> still PIVOT 2 (no new high, so
                                         NO Pivot 3 -- Peak would be 19200<19500)
                                           /
                                   rally to NEW HIGH 20600 (> 19500 = Peak2) ✓
                                          \  fall 5% from 20600 -> 19570 trigger
                                           19500 <= 19570 => PIVOT 3 @ 19500
                                           (Peak2 20600 > Peak1 19500  ✓)


================================================================================
 SECTION 4 — THE SLAB GRID (THE 2-D LOOKUP)
================================================================================

Rows    = ROC slabs (how FAR the market has moved).
Columns = active pivot (how MANY N% down-legs have formed).
Cells   = the strike offset to use (ITM/ATM/OTM, value, % or points).

Your example grid:

   SLAB     ROC band   | Pivot1 col | Pivot2 col | Pivot3 col
   -------- ---------- | ---------- | ---------- | ----------
   Slab 1   0 - 5 %    |  OTM 2%    |  OTM 1%    |  ATM
   Slab 2   5 - 10 %   |  OTM 1%    |  ATM       |  ITM 1%
   Slab 3   10 - 15 %  |  ATM       |  ITM 1%    |  ITM 2%
   Slab 4   15 - 20 %  |  ITM 1%    |  ITM 2%    |  ITM 3%
   Slab 5   20 % +     |  ITM 2%    |  ITM 3%    |  ITM 4%

Reading rule at any entry:
   1. Find the active pivot     -> picks the COLUMN.
   2. Compute ROC, find its band-> picks the ROW.
   3. The cell = the offset fed into the EXISTING strike resolver.

Notice the diagonal gradient: down-and-right = deeper ITM. Persisting,
deepening down-moves push the sold strike steadily into the money.

  Date  Close  Pivot/Peak state                          Active ROC(cum  ROC(fall  Slab*  Cell*
                                                          pivot  vs18700) frm peak)        offset
  ----- -----  ---------------------------------------- ----- -------- --------- ------ ----------
  Wk0   18700  P1=18700, running_peak=18700               P1    0.0%     0.0%      Slab1  OTM 2%

  Wk5   19200  LOWER high (<19500): peak STAYS 19500       P2   +2.67%    -1.54%    Slab1* OTM 1%
  Wk6   18100  fall again, but NO new high => still P2     P2   -3.21%    -7.18%    Slab1* OTM 1%
  Wk7   20600  NEW HIGH > Peak1 => running_peak=20600(Pk2) P2   +10.16%   0.0%      Slab1  OTM 1%
  Wk8   19500  19500<=20600*.95(19570) => P3=19500        P3   +4.28%    -5.34%    Slab1* ATM

HOW EACH ENTRY'S STRIKE IS PICKED (using FALL-FROM-PEAK ROC = answer A3):

  Wk0  ATM=18700. Cell OTM 2% (PE=>lower). 18700*0.98=18326 -> SELL 18350 PE.
  Wk3  On Pivot 2 col. Fall from peak 19500 = -5.13% -> Slab2? edge; take Slab1

       SELL 19500 PE.
  Wk9  Still Pivot 3, deeper fall from peak 20600 to 17500 = -15.05% -> Slab4
       region; with Slab2 x Pivot3 example grid = ITM 1%. ATM=17500 ->

READING OF THE BEHAVIOUR (with Peak2>Peak1 enforced):
  The column (Pivot 1->2->3) now advances ONLY on genuine higher-high-then-fall
  cycles, so it is a "number of confirmed new-peak selloffs" counter, not just a
  drawdown counter. Between those, Pivot 2 trails the low and the strike is
  driven mostly by the ROW (how far below the peak we are).

  *** IMPORTANT INTERACTION (re-confirm Question A): with the strict-higher-peak
  rule, "ROC cumulative from Pivot 1" frequently reads POSITIVE exactly when a
  new pivot forms (because a new ALL-TIME high just printed). That makes A1+B1
  (downside-only) sit in Slab 1 most of the time. A3 (FALL FROM LATEST PEAK) is
  the basis that stays meaningful under this rule -- so this note nudges the
  recommendation for Question A toward A3. PLEASE CONFIRM A vs the new rule. ***

QUESTION A — ROC: measured from WHICH point? (THE #1 BLOCKER)
--------------------------------------------------------------------------------
WHY: It changes which slab row is picked, i.e. the strike, on every entry.

OPTIONS:
  A1) Cumulative from Pivot 1 (the original 18700) for the whole phase.
  A2) From the ACTIVE pivot's close; resets toward 0 each new pivot.
  A3) Fall from the latest PEAK (how far below Peak N we currently are).

TRADE EXAMPLE (spot 14500 at Wk8; Pivot1=18700, Pivot3=16300, Peak3=16300):
  A1: ROC = (14500-18700)/18700 = -22.46% -> Slab 5 -> ITM 4% -> SELL 15100 PE
  A2: ROC = (14500-16300)/16300 = -11.04% -> Slab 3 -> ITM 2% -> SELL 16650 PE
  A3: ROC = (14500-16300)/16300 = -11.04% (peak3=pivot3 here) -> Slab 3 -> ITM 2%
  => A1 sells a much deeper ITM strike than A2/A3 for the same market.

MY DEFAULT: *** REVISED after the "Peak2 > Peak1" rule -> now A3 (FALL FROM
LATEST PEAK). *** Under the strict-higher-peak rule, a new pivot forms right
after a NEW high, so A1 (cumulative from Pivot 1) is usually POSITIVE at that
moment and would collapse to Slab 1 under downside-only handling. A3 keeps the
ROW meaningful (how far below the latest peak we are). The columns still carry
the "which pivot" axis independently. If you instead want A1, we should pair it
with B2 (absolute magnitude) so rallies also populate slabs. PLEASE CONFIRM.

QUESTION B — ROC sign: absolute magnitude, or downside-only / signed?
--------------------------------------------------------------------------------
WHY: Your slabs are written as positive bands but the whole staircase is falls.
     What happens when the market is UP?

OPTIONS:
  B1) Downside-only: feature engages only on falls; if ROC >= 0 stay in Slab 1 /
      Pivot 1 (default OTM) — a purely defensive mechanism.
  B2) Absolute magnitude: a 12% RISE and a 12% FALL both map to Slab 3.
  B3) Two separate grids (one for up moves, one for down moves).

TRADE EXAMPLE (market RISES to 20900, +11.8% from 18700):
  B1: ROC treated as 0 (no fall) -> Slab 1, Pivot 1 -> OTM 2% (default behaviour).
  B2: |+11.8%| -> Slab 3 -> ATM (Pivot1 col) -> strike pulled to ATM on a rally.
  B3: uses the user's separate "up" grid.

MY DEFAULT: B1 (downside-only). The example table and the staircase are entirely
fall-driven; treating rallies as "stay default" is the least surprising.
