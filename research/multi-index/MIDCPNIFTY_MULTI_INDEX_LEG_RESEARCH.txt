------------------------------------------------------------------------------
1. WHAT WE ARE BUILDING
------------------------------------------------------------------------------
HARD RULE: this is a COMPLETELY NEW, SELF-CONTAINED feature. No existing core
logic is edited. The new multi-index/multi-expiry path is built as a separate
module + separate endpoint, and it REUSES existing helper functions read-only
(imports them, never modifies them). A routing gate sends only the new strategy
shape to the new path; every existing strategy keeps running the existing code
unchanged. See section 9 for the isolation architecture.

A backtest where a single strategy can hold legs on DIFFERENT indices AND on
DIFFERENT expiry cycles at the same time, e.g.:
  - NIFTY      options leg  on WEEKLY expiry
  - MIDCPNIFTY futures leg  on MONTHLY expiry
  - MIDCPNIFTY options leg  on MONTHLY expiry

Each leg trades on ITS OWN expiry. The tradesheet is cut at the SHORTEST cadence
(weekly if any weekly leg exists); the longer (monthly) legs are CARRIED and
MARKED-TO-MARKET at each shorter-cadence boundary, and only actually settle/roll
at their own monthly expiry. This is exactly the mechanic the existing
"Call_Weekly_Sell_Put_Monthly" strategy already uses (weekly call leg + monthly
put leg) - we are generalising it to MULTIPLE INDICES.

The existing NIFTY-only strategies and the existing NIFTY + Midcap100
(hypothetical index) overlay are NOT changed.

HARD LIMIT: MIDCPNIFTY data starts 24-Jan-2022. Any cadence row before that date

2a. LIQUIDITY REALITY (interpretation)
MIDCPNIFTY OPTIONS liquidity sits almost entirely in the FRONT WEEKLY contract in
the OLD regime; the MONTHLY/far contracts barely trade and their daily close is a
THEORETICAL SETTLEMENT MARK, not a traded price (e.g. 01-Feb-2024 monthly turnover
= 24 vs front-weekly 30,097,826). So in the OLD regime a MIDCPNIFTY MONTHLY OPTION
leg is marked on stale prices. The MIDCPNIFTY FUTURES leg is liquid throughout.
From late-2024 MIDCPNIFTY weeklies were discontinued, so the monthly IS the traded
contract and the option leg becomes clean. The tradesheet must carry a
liquidity/turnover flag so a frozen price is never silently counted as real.

4. THE MODEL - WEEKLY CADENCE + HYPOTHETICAL WEEKLY MARKS
------------------------------------------------------------------------------
(This is the confirmed model, taken from Call_Weekly_Sell_Put_Monthly and
extended to multiple indices.)

DEFINITIONS
  - CADENCE  = the shortest leg's expiry cycle in the strategy (weekly if any
               weekly leg exists; otherwise monthly). One tradesheet ROW per
               cadence cycle, "Expiry-To-Expiry" (entry = previous cadence expiry,
               exit = this cadence expiry).
  - SHORT LEG (e.g. NIFTY weekly): freshly entered every cadence cycle, settled at
               its own (weekly) expiry. New strike each cycle.
  - LONG LEG  (e.g. MIDCPNIFTY monthly future / option): held as ONE continuous
               position, MARKED at each cadence boundary using a "Hypothetical
               ExitPrice" (the contract's close that day - a mark, not a trade).
               Next cycle's EntryPrice = this cycle's Hypothetical ExitPrice
               (the carry). The long leg only ACTUALLY trades at:
                 (i)  open,
                 (ii) a re-strike (spot moved enough to reselect strike), or
                 (iii) its own monthly expiry (settle + roll to next month).

NET P&L per cadence row = short-leg P&L + the cadence-period MARK-CHANGE of every
carried long leg. Cumulative / Peak / DD / %DD are computed at the cadence
(weekly) level.

TWO LAYERS OF ROLL
  1. SHORT leg rolls every cadence cycle (new weekly contract + strike).
  2. LONG leg rolls only at ITS OWN monthly expiry (and re-strikes on spot moves).

------------------------------------------------------------------------------
5. HOW EVERY EXISTING FEATURE WORKS UNDER THIS MODEL
------------------------------------------------------------------------------
  Feature           Behaviour
  Filter (patches)  The last cadence row of each patch is clamped to the patch
                    End date -> Exit Reason FILTER_END. Trades never cross a patch
                    boundary. Long legs are settled/marked at the clamp date.
  Re-entry          Within a cadence cycle, if a leg's SL/target fires, a new
                    cadence sub-row opens same day (ReEntryIndex) and runs to the
                    cycle/patch end. Short and long legs both follow.
  Rollover          Native to the model: the SHORT leg rolls each cadence; each
                    LONG leg rolls at its own monthly expiry (and re-strikes).
  Spot-adjustment   A +/-X% breach truncates the cadence row to the breach date,
                    tags SPOT_ADJ_*, and spawns a same-day re-entry row. Long legs
                    are marked/settled at the breach date.
  MAE / MFE         Per leg, over each leg's actual held window (cadence slice for
                    long legs), using that instrument's real high/low.
  Lot size          Per-symbol, date-dependent. NIFTY uses NIFTY lots; MIDCPNIFTY
                    uses MIDCPNIFTY lots (75 -> 120 -> 140 -> 120).
  Strike selection  ATM +/- % with ITM/OTM rounding, per leg, per index interval
                    (NIFTY 50, MIDCPNIFTY 25). Short legs re-strike each cadence;
                    long legs re-strike on spot move.

    carried monthly leg.

7. TRADESHEET STRUCTURE (per-leg column blocks)
------------------------------------------------------------------------------
The sheet carries ONE column block per leg, mirroring the existing
weekly+monthly sample:
  <Leg> Expiry | <Leg> Strike | <Leg> Entry Turnover | <Leg> EntryPrice |
  <Leg> Exit Turnover | <Leg> Hypothetical ExitPrice | <Leg> P&L
plus shared cadence columns:
  Entry Date | Exit Date | Entry Spot | Exit Spot | Spot P&L |
  Net P&L | Net P&L/Spot Pct | Cumulative | Peak | DD | %DD
Each MIDCPNIFTY leg block also carries a liquidity/turnover flag so stale
old-regime monthly-option marks are visible, not silently booked.

GENERATION PIPELINE
  1. Engine builds, per cadence cycle: short legs (fresh entry->settle) and long
     legs (carried, marked via Hypothetical ExitPrice; settle/roll at own expiry).
  2. Per-leg blocks + Net P&L are assembled per cadence row.
  3. Analytics add Cumulative, Peak, DD, %DD at cadence level.
  4. Workbook tabs: Trade Sheet, Summary, Patch wise (when filter present).
Summary metrics (Overall Profit, Win %, CAGR, Max DD + days/period, Return/MaxDD,
streaks, monthly grid, Live DD, outlier-stripped Live DD) are computed from the
Net P&L / Net-Spot-% columns at cadence level.

10. OPEN DECISIONS (need a call before build)
------------------------------------------------------------------------------
  1. Cadence rule: shortest-leg expiry drives the row cadence (weekly if any weekly
     leg). Confirm.
  2. Long-leg re-strike rule: when exactly does a carried monthly leg re-strike
     (every cadence on spot move? only on its own expiry? a threshold)? Match the
     existing weekly+monthly strategy's rule.
  3. Long-leg roll timing: settle + reopen on the monthly expiry's close
     (recommended), or earlier (N days before expiry).
  4. Old-regime MIDCPNIFTY monthly OPTION pricing: use settled marks with a
     liquidity flag (recommended) vs disallow the option leg pre-late-2024.
  5. MAE/MFE basis for carried long legs: per-cadence slice (recommended) vs over
     the full monthly hold.

------------------------------------------------------------------------------
11. ONE-LINE SUMMARY
------------------------------------------------------------------------------
Each leg trades on its own index and its own expiry; the tradesheet is cut at the
shortest cadence (weekly); short legs roll every cycle while long (monthly) legs
are carried and marked weekly via a Hypothetical ExitPrice and settle/roll at
their own monthly expiry - exactly the existing Call_Weekly_Sell_Put_Monthly
mechanic, extended to NIFTY + MIDCPNIFTY, with existing strategies untouched.
